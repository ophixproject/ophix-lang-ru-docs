`ophix-docs` — необязательный плагин, добавляющий встроенную документацию в административную панель Django. Каждое установленное приложение может поставлять собственную документацию в формате Markdown; команда управления импортирует всё в базу данных, откуда оно отображается в панели администратора с подсветкой синтаксиса.

---

## Установка

```bash
pip install ophix-docs
ophix-manage migrate
```

После установки и применения миграций в панели администратора появляется раздел **Документация**.

---

## Импорт документации

Команда `ophix_docs_update` импортирует файлы Markdown в базу данных:

```bash
ophix-manage ophix_docs_update
```

По умолчанию она читает из пути, заданного в `OPHIX_DOCS_PATH` (по умолчанию папка `docs/` рядом с корнем проекта). Для импорта документации из установленных приложений:

```bash
# На сервере учётных данных:
ophix-manage ophix_docs_update \
  --include-app-docs ophix.core,ophix_creds,ophix_docs,ophix_theme_tools
```

`ophix_docs_update` работает **только в режиме добавления** — создаёт и обновляет страницы, но никогда их не удаляет. Для удаления страниц используйте `ophix_docs_purge`.

---

## Удаление документации

### Удалить определённые страницы по slug

```bash
ophix-manage ophix_docs_purge мой-slug
```

### Удалить все страницы

```bash
ophix-manage ophix_docs_purge --all
```

### Удалить страницы, исходные файлы которых были удалены

```bash
ophix-manage ophix_docs_purge --deleted
```

Все режимы поддерживают `--dry-run`:

```bash
ophix-manage ophix_docs_purge --deleted --dry-run
```

## Формат файлов Markdown

Каждая страница документации — это файл `.md` с блоком YAML-метаданных:

```text
---
title: Заголовок моей страницы
slug: мой-slug
order: 10
section: Мой раздел
---

## Первый раздел

Содержимое страницы...
```

### Поля метаданных

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `title` | Да | Отображаемое имя в навигации панели администратора |
| `slug` | Да | Уникальный идентификатор — должен быть уникальным среди всей импортированной документации |
| `order` | Да | Позиция сортировки внутри раздела |
| `section` | Да | Название раздела, к которому принадлежит страница |

---

## Разделы

Разделы группируют связанные страницы в навигации. Каждое приложение, поставляющее документацию, должно включать файл `sections.yaml`:

```yaml
sections:
  - name: Мой раздел
    collapsed: false
```

## Пользовательская документация оператора

Операторы могут добавлять собственные страницы документации. Настройте путь в `.env`:

```ini
OPHIX_DOCS_PATH=/home/websites/credserver/docs
```

## Экспорт документации

```bash
ophix-manage ophix_docs_export мой-slug --output ./docs/
```

## Список источников документации

```bash
ophix-manage ophix_docs_list_sources
```

## Настройки

| Настройка | По умолчанию | Описание |
| --- | --- | --- |
| `OPHIX_DOCS_ENABLED` | `true` | Установите `false`, чтобы скрыть раздел документации из панели администратора |
| `OPHIX_DOCS_PATH` | `BASE_DIR/docs` | Путь к основной папке документации |
| `OPHIX_DOCS_APP_LABEL` | `Documentation` | Метка раздела в панели администратора |
